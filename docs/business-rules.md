# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 任意时刻已收金额 + 未收金额 = 订单金额：收款增加已收、冲正减少已收，二者都只改变构成，不改变订单金额。
- 核销用于把已登记并确认的收款金额认定为已核销：核销后订单已核销金额（`reconciled_cents`）累加，作为冲正后已收金额的下限；核销只改变认定口径，不改变已收、未收与订单金额。
- 核销金额必须大于零，且累计核销不得超过当前已收金额。非法核销必须被拒绝，且不改变任何已有金额、状态与核销留痕；拒绝原因（409 响应体说明具体原因）必须与订单不存在/跨租户（404）、请求标识冲突（422）区分。
- 每笔生效的核销作为独立业务事实留痕（`reconciliation_records`），可按订单按发生顺序读出每笔核销金额与结果；当前已核销金额 = 核销留痕合计。
- 冲正用于纠正已登记的收款：冲正后已收金额减少、未收金额相应增加，仍有未收金额时订单回到未收清（`accepted`）状态；之后可继续登记收款，收清后重新进入已结清（`settled`）状态。
- 冲正金额必须大于零，且不得超过当前已收金额（冲正后已收不得小于零）；冲正也不得使已收金额小于已核销金额（`reconciled_cents`），该限制在核销生效后立即起作用。非法冲正必须被拒绝，且不改变任何已有金额、状态与留痕。
- 冲正失败原因必须与其他失败区分：金额非法返回 409（响应体说明具体原因），订单不存在或跨租户访问返回 404，请求标识冲突返回 422。
- 每笔生效的收款与冲正都作为独立业务事实留痕（`payment_records`、`reversal_records`），可按订单按发生顺序读出每笔金额与冲正结果；当前已收 = 收款留痕合计 − 已生效冲正留痕合计。
- 订单更正用于纠正受理时录错的订单金额、币种或订单标识：更正成功后订单按新内容（新金额、新币种、新标识）生效，收款/冲正/核销与金额守恒规则在更正后的订单上照常适用。
- 只有尚未产生任何收款、冲正、核销业务事实的订单才允许更正：`paid_cents`、`reconciled_cents` 均为 0，且不存在任何收款、冲正、核销留痕（收款后即使全额冲正使已收归零，留痕仍在，仍不可更正）。一旦存在上述任一事实，更正必须被拒绝。
- 更正后的金额必须是大于零的整数最小货币单位，币种限服务已支持币种，更正后的订单标识不能为空；同租户下若新标识已属于其他订单也必须拒绝（跨租户同名不构成冲突）。非法或不被允许的更正返回 409（响应体说明具体原因），订单金额、币种、标识、状态与全部留痕保持不变。
- 更正失败原因必须与其他失败区分：输入非法或业务上不允许返回 409（响应体说明具体原因），订单不存在或跨租户访问返回 404，请求标识冲突返回 422。
- 更正可能改变订单标识，而旧标识在改名后会被释放、可能被后续新受理的订单复用；每张订单以受理时分配的不可变链路键 `ledger_id` 串联，使更正留痕在改名后仍可按当前标识读出，且不会串到复用了旧标识的新订单。
- 每一次更正（含被拒绝的更正）都作为独立业务事实留痕（`correction_records`），记录更正前后的订单标识、金额、币种与生效/拒绝结果（`applied`/`rejected`，被拒绝时附拒绝原因），可按订单按发生顺序读出；订单不存在/跨租户访问（404）与请求标识冲突（422）不写留痕。
- 跨租户读取（含冲正登记、核销登记、更正登记与各类留痕读取）一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 请求标识与幂等

- 调用方可在受理订单、登记收款、冲正收款、核销与更正订单时通过请求头 `Idempotency-Key` 携带请求标识；同一租户内同一请求标识代表同一次业务请求。
- 同租户同标识的重复提交（含网络重试、重复点击、并发提交）回放首次执行的状态码与响应体：不新增受理记录、不重复累加收款、不重复冲正、不重复累加核销、不重复更正，不改变已有金额与状态。
- 首次请求的业务结论也被固化：首次即 409/404 的请求，重复提交时仍回放同一结论。受理/收款/冲正/核销的冲突结论不写订单与对应业务流水；更正的 409 拒绝结论会固化一条 `rejected` 更正留痕（仅首次这一条），订单本身及金额、标识、状态不变；任何操作的 404（不存在/跨租户）与 422（请求标识冲突）都不写留痕。
- 同一请求标识被用于不同业务内容（订单标识、订单金额、币种，收款金额，冲正金额，核销金额，更正后的订单标识/金额/币种，或目标订单）或不同操作类型（受理/收款/冲正/核销/更正）时，返回 422 拒绝，且不改变任何已有数据。
- 幂等作用域为（租户, 请求标识），跨租户重用相同标识互不影响。
- 并发提交收款、冲正、核销与更正（无论是否同一请求标识）时，数据库写事务在库级串行化：每个操作只生效一次，读回的金额与留痕顺序一致，累计核销不超过累计已收，不会出现负的已收金额或与留痕对不上的合计。
- 幂等记录、收款、冲正、核销与更正留痕均持久化于数据库，服务重启后继续有效；重启前已处理的请求标识在重启后重复提交仍按重复请求回放，已拒绝的冲突请求仍被拒绝。
- 未携带请求标识的请求按原有方式处理：同一租户重复受理仍返回 409，超额收款仍返回 409，跨租户读取仍按不存在处理；更正同样按普通单次操作处理（每次提交都会独立判定并留痕）。
