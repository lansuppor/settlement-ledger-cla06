# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 任意时刻已收金额 + 未收金额 = 订单金额：收款增加已收、冲正减少已收，二者都只改变构成，不改变订单金额。
- 核销用于把已登记并确认的收款金额认定为已核销：核销后订单已核销金额（`reconciled_cents`）累加，作为冲正后已收金额的下限；核销只改变认定口径，不改变已收、未收与订单金额。
- 核销金额必须大于零，且累计核销不得超过当前已收金额。非法核销必须被拒绝，且不改变任何已有金额、状态与核销留痕；拒绝原因（409 响应体说明具体原因）必须与订单不存在/跨租户（404）、请求标识冲突（422）区分。
- 每笔生效的核销作为独立业务事实留痕（`reconciliation_records`），可按订单按发生顺序读出每笔核销金额与结果；当前已核销金额 = 核销留痕合计。
- 冲正用于纠正已登记的收款：冲正后已收金额减少、未收金额相应增加，仍有未收金额时订单回到未收清（`accepted`）状态；之后可继续登记收款，收清后重新进入已结清（`settled`）状态。
- 冲正金额必须大于零，且不得超过当前已收金额（冲正后已收不得小于零）；冲正也不得使已收金额小于已核销金额（`reconciled_cents`），该限制在核销生效后立即起作用。非法冲正必须被拒绝，且不改变任何已有金额、状态与留痕。
- 冲正失败原因必须与其他失败区分：金额非法返回 409（响应体说明具体原因），订单不存在或跨租户访问返回 404，请求标识冲突返回 422。
- 每笔生效的收款与冲正都作为独立业务事实留痕（`payment_records`、`reversal_records`），可按订单按发生顺序读出每笔金额与冲正结果；当前已收 = 收款留痕合计 − 已生效冲正留痕合计。
- 跨租户读取（含冲正登记与留痕读取）一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 请求标识与幂等

- 调用方可在受理订单、登记收款、冲正收款与核销时通过请求头 `Idempotency-Key` 携带请求标识；同一租户内同一请求标识代表同一次业务请求。
- 同租户同标识的重复提交（含网络重试、重复点击、并发提交）回放首次执行的状态码与响应体：不新增受理记录、不重复累加收款、不重复冲正、不重复累加核销，不改变已有金额与状态。
- 首次请求的业务结论也被固化：首次即 409/404 的请求，重复提交时仍回放同一结论；只有业务真正成功的那一次落库，冲突结论不会写订单、收款、冲正或核销流水。
- 同一请求标识被用于不同业务内容（订单标识、订单金额、币种，收款金额，冲正金额，核销金额，或目标订单）或不同操作类型（受理/收款/冲正/核销）时，返回 422 拒绝，且不改变任何已有数据。
- 幂等作用域为（租户, 请求标识），跨租户重用相同标识互不影响。
- 并发提交收款、冲正与核销（无论是否同一请求标识）时，数据库写事务在库级串行化：每个操作只生效一次，读回的金额与留痕顺序一致，累计核销不超过累计已收，不会出现负的已收金额或与留痕对不上的合计。
- 幂等记录、收款、冲正与核销留痕均持久化于数据库，服务重启后继续有效；重启前已处理的请求标识在重启后重复提交仍按重复请求回放，已拒绝的冲突请求仍被拒绝。
- 未携带请求标识的请求按原有方式处理：同一租户重复受理仍返回 409，超额收款仍返回 409，跨租户读取仍按不存在处理。

## 批量导入

- 批量导入接受逗号分隔的订单行文本，每行含租户、订单标识、订单金额、币种四个字段；逐行校验、逐行独立事务受理，任一行的问题不影响其他行的受理结果（部分成功）。
- 导入结果计数闭合：提交行数 = 成功行数 + 跳过行数 + 失败行数；失败清单逐行给出物理行号、订单标识（若能解析出）与可区分的原因：字段缺失或格式错误、金额不是正整数、币种不受支持、订单标识与已有订单的业务内容不一致；内容完全一致的同租户重复受理记为跳过并给出「订单标识已存在」原因。
- 批量导入与逐张受理遵守完全相同的规则：金额为最小货币单位的正整数、币种只接受受支持币种、租户互相隔离；导入成功的订单可按标识读取，收款、冲正、核销及其请求标识幂等规则照常适用；导入写入的订单不携带请求标识。
- 重复导入安全：同租户同订单标识且金额币种完全一致的行按跳过处理，不重复受理、不改变已有订单的金额与状态；内容不一致的行按失败处理，同样不改变已有数据。
- 导入中途失败（解析中断或进程退出）时已受理的行保持生效；重试同一份输入时成功过的行按跳过处理、原先失败的行按其结果重新判定，不产生重复订单，每行结论唯一确定，同一订单标识不会因重复导入产生两条受理记录或两笔金额变化。
