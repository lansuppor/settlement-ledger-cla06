# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 任意时刻 已收金额 + 未收金额 = 订单金额；收款增加已收，冲正减少已收，两者相互制约、保持守恒。
- 冲正用于纠正已登记的收款：冲正后已收金额不得小于零，也不得小于已核销金额（当前无核销能力，已核销金额恒为 0，结构上以 `written_off_cents` 兜底）。
- 冲正金额必须大于零且不超过当前已收金额（扣除已核销部分）；不合法的冲正必须被拒绝，且不改变任何金额、状态与冲正留痕。
- 每笔成功的冲正作为独立业务事实留痕（`reversals` 表）：记录冲正金额、冲正后的已收/未收金额与请求标识，可按订单按序读出。
- 订单被冲正到仍有未收金额时可继续登记收款，收清后重新进入已结清状态。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 请求标识与幂等

- 调用方可在受理订单、登记收款与收款冲正时通过请求头 `Idempotency-Key` 携带请求标识；同一租户内同一请求标识代表同一次业务请求。
- 同租户同标识的重复提交（含网络重试、重复点击、并发提交）回放首次执行的状态码与响应体：不新增受理记录、不重复累加收款、不重复冲减已收、不改变已有金额与状态。
- 首次请求的业务结论也被固化：首次即 409/404 的请求，重复提交时仍回放同一结论；只有业务真正成功的那一次落库，冲突结论不会写订单、收款或冲正留痕。
- 同一请求标识被用于不同业务内容（订单标识、订单金额、币种，或收款/冲正金额、目标订单）或不同操作类型（受理/收款/冲正）时，返回 422 拒绝，且不改变任何已有数据。
- 幂等作用域为（租户, 请求标识），跨租户重用相同标识互不影响。
- 并发提交同一请求标识时，数据库写事务在库级串行化：最终只有一次请求真正产生业务效果，其余请求在首条记录提交后读到它并回放同一结果。
- 幂等记录持久化于数据库（`idempotent_requests` 表），服务重启后继续有效；已拒绝的冲突请求在重启后重复提交仍被拒绝，不会被误判为新请求。
- 未携带请求标识的请求按原有方式处理：同一租户重复受理仍返回 409，超额收款仍返回 409，跨租户读取仍按不存在处理。
