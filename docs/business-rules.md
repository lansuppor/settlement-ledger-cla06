# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 请求标识与幂等

- 调用方可在受理订单与登记收款时通过请求头 `Idempotency-Key` 携带请求标识；同一租户内同一请求标识代表同一次业务请求。
- 同租户同标识的重复提交（含网络重试、重复点击、并发提交）回放首次执行的状态码与响应体：不新增受理记录、不重复累加收款、不改变已有金额与状态。
- 首次请求的业务结论也被固化：首次即 409/404 的请求，重复提交时仍回放同一结论；只有业务真正成功的那一次落库，冲突结论不会写订单或收款。
- 同一请求标识被用于不同业务内容（订单标识、订单金额、币种，或收款金额、目标订单）或不同操作类型（受理/收款）时，返回 422 拒绝，且不改变任何已有数据。
- 幂等作用域为（租户, 请求标识），跨租户重用相同标识互不影响。
- 并发提交同一请求标识时，数据库写事务在库级串行化：最终只有一次请求真正产生业务效果，其余请求在首条记录提交后读到它并回放同一结果。
- 幂等记录持久化于数据库（`idempotent_requests` 表），服务重启后继续有效；已拒绝的冲突请求在重启后重复提交仍被拒绝，不会被误判为新请求。
- 未携带请求标识的请求按原有方式处理：同一租户重复受理仍返回 409，超额收款仍返回 409，跨租户读取仍按不存在处理。
