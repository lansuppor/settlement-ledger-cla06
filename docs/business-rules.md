# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 任意时刻已收金额 + 未收金额 = 订单金额：收款增加已收、冲正减少已收，二者都只改变构成，不改变订单金额。
- 核销用于把已登记并确认的收款金额认定为已核销：核销后订单已核销金额（`reconciled_cents`）累加，作为冲正后已收金额的下限；核销只改变认定口径，不改变已收、未收与订单金额。
- 核销金额必须大于零，且累计核销不得超过当前已收金额。非法核销必须被拒绝，且不改变任何已有金额、状态与核销留痕；拒绝原因（409 响应体说明具体原因）必须与订单不存在/跨租户（404）、请求标识冲突（422）区分。
- 每笔生效的核销作为独立业务事实留痕（`reconciliation_records`），可按订单按发生顺序读出每笔核销金额与结果；当前已核销金额 = 核销留痕合计。
- 冲正用于纠正已登记的收款：冲正后已收金额减少、未收金额相应增加，仍有未收金额时订单回到未收清（`accepted`）状态；之后可继续登记收款，收清后重新进入已结清（`settled`）状态。
- 冲正金额必须大于零，且不得超过当前已收金额（冲正后已收不得小于零）；冲正也不得使已收金额小于已核销金额（`reconciled_cents`），该限制在核销生效后立即起作用。非法冲正必须被拒绝，且不改变任何已有金额、状态与留痕。
- 冲正失败原因必须与其他失败区分：金额非法返回 409（响应体说明具体原因），订单不存在或跨租户访问返回 404，请求标识冲突返回 422。
- 退款用于把已收金额真实出账退回付款方（与冲正不同：冲正纠正录错的收款登记，退款是真实退钱）：退款后已收金额减少、未收金额相应增加，仍有未收金额时订单回到未收清（`accepted`）状态；之后可继续收款，收清后重新进入已结清（`settled`）状态。订单金额与已核销金额不因退款改变。
- 退款金额必须是大于零的整数最小货币单位；累计退款不得超过累计已收减去累计已退（即退款后已收不得为负），退款也不得使已收金额低于已核销金额（`reconciled_cents`，核销下限对退款同样起作用）。非法退款必须被拒绝，且不改变订单金额、已收、未收、已核销、状态与任何留痕。
- 退款失败原因必须与其他失败区分：金额非法返回 409（响应体说明具体原因：金额非正整数 / 退款后已收为负 / 退款后已收低于已核销），订单不存在或跨租户访问返回 404，请求标识冲突返回 422。
- 每笔退款（含被拒绝的结论）都作为独立业务事实留痕（`refund_records`），可按订单按发生顺序读出每笔退款金额、结果（applied/rejected）、拒绝原因、退款原因、退款后已收、请求标识与时间；任意时刻已收 = 收款留痕合计 − 已生效冲正留痕合计 − 已生效退款留痕合计，且不低于已核销、不为负。
- 每笔生效的收款与冲正都作为独立业务事实留痕（`payment_records`、`reversal_records`），可按订单按发生顺序读出每笔金额与冲正结果；当前已收 = 收款留痕合计 − 已生效冲正留痕合计。
- 业务时间线（`timeline_events`）把一张订单从受理至今的全部业务事实合并留痕：每个到达既有订单的业务请求至多追加一条，受理与收款记录生效结论，冲正、核销、更正、退款的生效与被拒绝结论各占一条并注明拒绝原因；条目按全库单调序号排列即业务发生顺序，跨环节排序不依赖各留痕表各自的时间字段，重复读取、并发读取与服务重启后内容与顺序不变；订单更正改名时该订单的时间线随订单迁移到新标识。
- 订单更正用于修正受理时录错的订单金额、币种或订单标识：更正成功后订单按新内容生效，订单按新标识可读；已收、未收、已核销与状态按更正后的金额重新呈现（更正只允许发生在尚无任何业务事实的订单上，故更正时这些金额必然均为 0、状态为 accepted）。
- 只有尚未产生任何收款、冲正、退款与核销的订单才允许更正：`paid_cents`、`reconciled_cents` 均为 0，且没有任何收款、冲正、退款、核销留痕（即使冲正或退款后已收已回到 0，只要存在留痕即视为已产生业务事实）。一旦存在任一业务事实，更正必须被拒绝，订单金额、币种、标识、状态与全部留痕保持不变。
- 更正后的金额必须是大于零的整数最小货币单位，币种限服务已支持币种，新订单标识不能为空；同租户下若新标识已被其他订单占用也必须拒绝（跨租户同名不构成冲突）。非法输入或业务拒绝返回 409（响应体说明具体原因），不改变任何已有数据；订单不存在或跨租户访问返回 404，请求标识冲突返回 422，三类失败须清楚区分。
- 更正产生的所有结论（生效与各类拒绝）都作为独立业务事实留痕（`correction_records`），可按订单按发生顺序读出更正前后的订单标识、金额、币种、生效/拒绝结果与具体拒绝原因；生效留痕挂在更正后的订单标识上，拒绝留痕挂在原目标订单标识上，订单改名时其历史更正留痕随订单迁移到新标识。
- 跨租户读取（含冲正登记、核销登记、退款、订单更正与各留痕读取）一律按“不存在”处理，不得泄漏对象是否存在。
- 条件检索（`GET /orders`）按租户检索订单集合：状态（未收清/已结清，可同时包含两者）、币种、订单金额上下限均为可选条件，不给出视为不限制；一次返回条数 1~200，缺省 50，超出范围或条件非法返回 400；检索为只读，不改变任何订单金额、状态与留痕；命中为空返回空列表而不是错误。
- 检索结果按受理顺序稳定排列：以业务时间线中受理条目的全库单调序号为准（批量导入受理的多张订单按导入行先后排列），同一订单只出现一次；每条返回项与按标识读取订单的字段一致。
- 检索分页为键集分页：游标位置只由受理顺序序号表达，不含租户、订单标识或任何数据库内部位置；返回条数不足本次请求条数即为最后一页、游标为空，否则把游标原样回传继续取下一页。同一租户、同一筛选条件、同一游标的多次查询返回完全相同的订单集合与顺序；翻页期间同租户并发受理、收款、冲正、核销、更正与退款不会使已翻过的页重复出现、未翻到的页漏订单；服务重启后同一筛选与游标仍得到相同结果。
- 检索隔离照常成立：结果只包含请求头指定租户自己的订单，其他租户同名订单、筛选条件与游标都不得造成越界读取；缺少租户按既有规则返回 400。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 请求标识与幂等

- 调用方可在受理订单、登记收款、冲正收款、核销、退款与订单更正时通过请求头 `Idempotency-Key` 携带请求标识；同一租户内同一请求标识代表同一次业务请求。
- 同租户同标识的重复提交（含网络重试、重复点击、并发提交）回放首次执行的状态码与响应体：不新增受理记录、不重复累加收款、不重复冲正、不重复累加核销、不重复退款、不重复更正，不改变已有金额、标识与状态。
- 首次请求的业务结论也被固化：首次即 409/404 的请求，重复提交时仍回放同一结论；只有业务真正成功的那一次落库，冲突结论不会改变订单、收款、冲正、核销、退款或重复写入更正流水。
- 同一请求标识被用于不同业务内容（订单标识、订单金额、币种，收款金额，冲正金额，核销金额，退款金额或退款原因，更正的目标订单或更正后订单标识/金额/币种，或目标订单）或不同操作类型（受理/收款/冲正/核销/退款/更正）时，返回 422 拒绝，且不改变任何已有数据。
- 幂等作用域为（租户, 请求标识），跨租户重用相同标识互不影响。
- 并发提交收款、冲正、核销与退款（无论是否同一请求标识）时，数据库写事务在库级串行化：每个操作只生效一次，读回的金额与留痕顺序一致，累计核销不超过累计已收，不会出现负的已收金额或与留痕对不上的合计。
- 幂等记录、收款、冲正、核销与退款留痕均持久化于数据库，服务重启后继续有效；重启前已处理的请求标识在重启后重复提交仍按重复请求回放，已拒绝的冲突请求仍被拒绝。
- 未携带请求标识的请求按原有方式处理：同一租户重复受理仍返回 409，超额收款仍返回 409，跨租户读取仍按不存在处理。
